Program keys

Programs and scripts that use Grain's API each need a key of their own. A program key can add and remove that program's own tools, send requests and see their results. It can't change settings or tools, read your history, or approve anything Grain is asking you about. The key is shown once; Grain keeps only a fingerprint of it.

Getting started

Grain is a voice assistant that runs entirely on this computer. Whistle turns your speech into text, Grain checks it against your tools' phrases, and if nothing matches, Needle (a small AI) guesses which tool you meant. No internet needed, and nothing you say leaves your PC.

Before the first run: install the model files

Grain needs these two local files before it can understand speech or choose tools:

  • needle3.cact — Needle's tool-calling model
  • whistle.cact — Whistle's speech-to-text model

Download them from the official Cactus Compute model pages: Needle 3 and Whistle.

Place both files in the models folder beside Grain:

  • Installed version: the models\ folder beside Grain App.exe, normally inside the Grain installation folder.
  • Running from source: the repository's models\ folder, beside grain_app.py.

Grain does not download model files automatically. After copying both files, restart Grain. If either file is missing, Grain opens the model setup instructions automatically.

Starting Grain

  • Install Grain with Grain Setup. It installs just for you (no administrator rights) and adds Grain to the Start menu. Your settings, history, notes and your own tools live separately in your data folder, %APPDATA%\Grain, so updating or reinstalling never loses them.
  • The first time Grain starts, a short setup opens here: choose and test your microphone, pick your hotkey, and decide whether Grain starts with Windows. You can run it again from Settings.
  • A Grain icon appears in the system tray (near the clock; click ^ if it's hidden). The dot on it shows what Grain is doing:
    DotMeaning
    ⚪ greyLoading
    🔵 blueReady, waiting for the hotkey
    🟢 greenReady, listening for the wake word
    🔴 redListening to you
    🟠 orangeThinking
  • Only one Grain runs at a time: starting it again just opens this tool editor.
  • To remove Grain: Windows Settings → Apps → Installed apps → Grain → Uninstall. Your data is kept unless you tick “also delete my settings”.

Talking to Grain

  • Hotkey: press __HOTKEY__ (or click the tray icon), then speak. Grain stops listening when you pause.
  • Wake word: turn on Wake word mode in the tray menu, then start any command with __WAKE__, e.g. “__WAKE1__, open the editor”. This keeps the microphone open (other apps can still use it), and uses more CPU.
  • Chain commands with “then”: “open notepad then set a timer for five minutes”.
  • Results appear as Windows notifications. Everything is also logged in History.
  • The hotkey doesn't work while a window running as administrator is in front. Windows doesn't let ordinary programs see keys pressed in admin windows. Click another window first, or use wake word mode.

Set up Grain's model files

Grain needs two local Cactus Compute model files before it can transcribe speech or choose a tool:

  • needle3.cact — the local tool-calling model.
  • whistle.cact — the local speech-to-text model.

Download them only from the official Cactus Compute model pages: Needle 3 and Whistle. The Cactus runtime source and documentation are on GitHub.

Place both files in Grain's installed models folder. For a source checkout, that is models\ beside grain_app.py. For the installed Windows app, use the models\ folder beside Grain App.exe.

Grain does not download model files automatically. The files are used locally and must be present before restarting Grain.

Microphone and troubleshooting

Grain uses your microphone in shared mode, so calls, recorders and games keep working while it listens. Pick and test the mic in Settings; the test tells you whether the level is good, too quiet or silent. Wake word mode costs very little while it waits (a few percent of one CPU core).

You seeWhat it means and what to do
“No sound at all from …”The mic is sending pure silence. It's unplugged, muted, or a virtual mic (for example from a remote-desktop or streaming app) that isn't receiving audio. Pick another mic, or turn on microphone sharing in that app's settings.
“Didn't hear anything”Sound is arriving but Grain didn't detect speech within 5 seconds. Speak sooner or closer.
“No action for …”Nothing matched. Check what Grain heard in History, then add a phrase for it.
“Not sure (0.42) … skipped”The AI guessed but wasn't confident enough. Add a phrase so it doesn't need to guess, or a keyword if the tool's own words weren't in what you said.
“Couldn't run that: …”The AI picked a tool but with a missing or impossible detail. The message says which. A phrase fixes it.
History shows “Thank you.” you didn't sayIn wake-word mode, speech recognition sometimes hears a polite “Thank you.” in background noise. It's harmless: without the wake word, Grain ignores it. It's a known quirk, and we've decided to keep it because it's funny.
The hotkey does nothingIs an administrator window in front? (See Getting started.) Otherwise another program may already use the same keys: pick a different hotkey in Settings.
A notification says a tool didn't loadA tool file or plugin has a mistake. The message says which; open it in this editor or check the plugin file.

How Grain decides what to do

🎙 You speak→Whistle writes it down→Split on “then”→Matches a phrase?→else: AI guesses→Sure enough?→Safety check→✅ Runs
  1. Phrases first. If what you said fits one of a tool's phrases, Grain uses it straight away, with the exact words you said. This is fast and always right.
  2. Otherwise the AI guesses from the active profile's tool descriptions, and reports how sure it is (0–100%). Grain then checks the guess: unknown tools, missing details and wrong kinds of value (“louder” for up/down/mute) are refused with “Couldn't run that”, and spoken numbers like “twenty five” are converted.
  3. Confidence check. Guesses below __THRESHOLD__% are skipped (change confidence_threshold, or per tool under More options). If you didn't mention anything to do with the chosen tool (its name, keywords or phrase words), the AI must be at least 80% sure. That stops confident nonsense like “open the editor” turning into “pause the music”. Phrase matches always pass.
  4. Safety. “Just do it” tools run. “Ask me first” tools wait: say yes or cancel, or use the tray menu or the Try it tab, within __CONFIRM__ seconds. “Only when sure” tools need the AI to be at least 80% sure.
The AI is small (121 million parameters) and gets less accurate with more tools to choose from. Phrases and profiles are the two biggest ways to make Grain reliable.

Making tools

Open the Tools tab and press + New. Pick a template and fill in the steps. Your tool is saved as a file in your tools folder (%APPDATA%\Grain\tools) and works as soon as you save. No restart needed.

Opening programs

You don't need a tool for each program: “open …”, “launch …” or “start …” finds any program in your Start menu. Add your own speech aliases through app_aliases in settings.

Writing good phrases

  • Write them the way you actually talk: “open YouTube”, “youtube {query}”, “play {query} on youtube”.
  • Add short and long versions. Grain picks the most specific phrase that fits.
  • A phrase must match everything you said (capitals and punctuation don't matter), so “open youtube please” needs its own phrase.
  • {word} captures what you say there. Numbers can be spoken (“two” → 2). If a detail has Only allow these values, the spoken word must be one of them.
  • Check what Whistle actually heard in History, and add those spellings to your own app_aliases if needed.

Tool files by hand

Each tool is a JSON file in the tools folder; the editor writes the same format:

{
  "name": "open_youtube",
  "description": "Open YouTube, searching for a video if one is named.",
  "phrases": ["youtube {query}", "play {query} on youtube", "open youtube"],
  "parameters": {"query": {"type": "string", "required": false}},
  "action": {"type": "open", "target": "https://www.youtube.com/results?search_query={query}"},
  "safety": "run"
}

Python plugins

For tools that need real code, put a .py file in your plugins folder (%APPDATA%\Grain\plugins, or tray → Open plugins folder). Grain loads it immediately, and again whenever you save it.

from typing import Literal
from grain import tool, notify, open_target

@tool(safety="confirm", phrases=["restart {service}", "restart the {service} server"])
def restart_service(service: Literal["web", "database"]):
    "Restart one of my local servers."
    ...                      # your code here
    return f"restarted {service}"   # shown as the notification
  • The docstring's first line is the description the AI reads. Type hints become details: str, int, float, bool, or Literal[...] for a fixed list.
  • open_target("start:App Name") opens programs, files or URLs; notify("...") shows a tray notification later (timers, background jobs).
  • Plugins run on Grain's built-in Python, so they can use the standard library and the packages Grain includes, but not packages you install separately.
  • Examples: plugins\apps.py (opening programs, with an easy list to edit), plugins\everyday.py, plugins\dice.py.

Profiles

A profile is the set of tools the AI guesses between when nothing matches a phrase. Fewer tools means better guesses. Phrases work in every profile. Grain comes with five: default (everyday tools), gaming (open programs, media, volume), coding (programs, search, notes), media (video, media and volume) and system (lock, battery and system tools).

  • Make profiles in the Profiles tab by ticking tools, e.g. gaming (open programs, media, volume) and coding.
  • Choose one in the tray menu, or set Automatic and add rules like “when Code.exe is in front, use coding”. The app in front when you press the hotkey decides.
  • Aim for about 10 tools or fewer per profile. The editor warns you past that.

Improving accuracy and fine-tuning

Work through these in order; most people never need the last steps.

  1. Add phrases for the commands you use most. This fixes most problems instantly.
  2. Use profiles to keep the tool list short.
  3. Review History. For each command, answer 👍 or 👎 and pick what it should have done. Each answer becomes a training example built from your real words.
  4. Fine-tune once you have a good number of reviewed examples: a few hundred at minimum. Cactus recommends about 1,000 training examples plus 100 each for validation and testing. Press Download training data in History to get grain-training.jsonl, in the format both options below accept.

Option A: train on this PC (free)

Trains a small add-on (a LoRA adapter) for Needle on your own computer. Needs Python 3.9+ and a few GB of disk; a graphics card helps but isn't required. Open PowerShell in a folder of your choice first; the commands create a train-env folder there.

py -m venv train-env
train-env\Scripts\pip install "cactus-needle[train]"
train-env\Scripts\needle finetune grain-training.jsonl --epochs 3 --out my-adapter.safetensors
train-env\Scripts\needle build --lora my-adapter.safetensors --out models\needle3-mine.cact
Locally trained models don't report confidence, so Grain can't skip unsure guesses: anything the AI picks will run. Set risky tools to Ask me first before switching.

Option B: the Cactus platform (paid)

Cactus trains the whole model on their GPUs, keeps the confidence score working, and can generate extra synthetic examples from your tools. When this was written: Starter $19 one-off (3 fine-tunes, 30 days), Pro $99/month. Check current prices at cactuscompute.com/llms/pricing. You buy a plan and create an API key at cactuscompute.com/dashboard, upload your training, validation and test files, and download the finished .cact model.

Check it's actually better

Before training, put about 10–20% of your examples in a separate test file and leave them out of training. Then score the old and new models on it:

curl.exe -O https://cactuscompute.com/needle-fine-tuning/needle_eval.py
train-env\Scripts\python needle_eval.py models\needle3.cact test.jsonl
train-env\Scripts\python needle_eval.py models\needle3-mine.cact test.jsonl

Use your model

  1. Put the .cact file in your models folder: Settings → Models opens it (%APPDATA%\Grain\models).
  2. In Settings, set Model file to models\needle3-mine.cact and save. It takes effect on the next command; no restart needed.
  3. The model in use right now: __MODEL__. To go back, set it to models\needle3.cact.

Using the API

Other programs and scripts on this PC can use Grain through its local API at http://127.0.0.1:__PORT__. It only accepts connections from this computer, and every request needs a key in an Authorization: Bearer … header.

Give each program its own key. Make one in Settings → Program keys and hand it to the program, for example as its GRAIN_API_KEY environment variable. A program key can add and remove that program's own tools, send requests, and read Grain's status and the results of its own requests. It can't change settings or tools, read your history, or approve anything Grain is waiting to ask you about. Grain shows it once and keeps only a fingerprint of it; revoking it also removes the program's tools.

This page's own key (don't give it to programs):••••••••••••

The tool editor key is stored as api_token in %APPDATA%\Grain\settings.json and can do everything. Registering a program's tools needs a program key. To change the tool editor key, use Make a new tool editor key in Settings.

Send a command

PowerShell, with the program key in GRAIN_API_KEY:

$h = @{ Authorization = "Bearer $env:GRAIN_API_KEY" }
Invoke-RestMethod http://127.0.0.1:__PORT__/v1/interpret -Method Post -Headers $h `
  -ContentType "application/json" -Body '{"text": "open notepad", "execute": false}'

Python:

import json, os, urllib.request
request = urllib.request.Request(
    "http://127.0.0.1:__PORT__/v1/interpret", method="POST",
    data=json.dumps({"text": "open notepad", "execute": False}).encode(),
    headers={"Authorization": "Bearer " + os.environ["GRAIN_API_KEY"], "Content-Type": "application/json"})
print(json.load(urllib.request.urlopen(request))["results"])

"execute": false previews; leave it out to really run the tool. Each result has the calls chosen, confidence, whether it matched a phrase, the outcome and a message.

Give Grain tools from your own program

A program can register tools and get called back when someone uses them. This is ideal for robots and devices. It needs a program key, and the tools belong to that key's program. Callbacks must be on this PC.

POST /v1/tools
{
  "callback": "http://127.0.0.1:8790/",
  "tools": [{
    "name": "walk",
    "description": "Walk the robot a number of steps in one direction.",
    "parameters": {"direction": {"type": "string", "enum": ["forward", "back", "left", "right"]},
                   "steps": {"type": "integer", "required": false}},
    "phrases": ["walk {direction} {steps} steps", "walk {direction}"]
  }]
}

When the tool is used, Grain sends POST {"tool": "walk", "arguments": {"direction": "forward", "steps": 3}} to your callback; reply with {"result": "walked 3 steps"} to show it in the notification. Remove your tools with DELETE /v1/tools. A complete working example is in examples\remote_tool_client.py.

All endpoints

RequestWhat it does
GET /v1/statusProfile, tools listening, microphone, model, load errors
POST /v1/interpret{text, execute?, profile?}: understand (and run) a command
GET /v1/toolsEvery tool, where it comes from, and whether it's listening
POST /v1/tools · DELETE /v1/tools?client=Register or remove your program's tools
GET / PUT / DELETE /v1/tool_files/{name}Read, create or delete a tool file
GET /v1/pending · POST /v1/pending/{id}/confirm or /cancelCommands waiting for an OK
GET /v1/history · POST /v1/history/{id}/correctionThe log, and your corrections: {calls: [...]}, or [] for “nothing”
GET /v1/training_dataReviewed commands as fine-tuning data (JSONL)
GET / PUT /v1/profiles{profiles, profile_rules, active_profile}
GET /v1/events?after=N&timeout=25Wait for new results (long polling)
GET / POST /v1/keys · DELETE /v1/keys/{id}List, make ({client}) or revoke program keys

Program keys can use GET /v1/status, POST /v1/interpret, POST and DELETE /v1/tools (their own tools only) and GET /v1/events (their own results only). Everything else needs the tool editor key.

Errors come back as {"error": {"code", "message"}} with status 400 (bad request), 401 (missing or unknown key), 403 (not from this PC, or not allowed with this key), 404, 409 (name already taken) or 413 (request too large).
